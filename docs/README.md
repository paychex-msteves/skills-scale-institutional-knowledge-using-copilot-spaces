# OctoAcme Project Management

This folder is the entry point for OctoAcme's project management process documentation. OctoAcme uses a customer-first, iterative approach: projects begin by agreeing on the problem, measurable outcomes, stakeholders, and initial risks; approved work is then planned as prioritized, estimated increments with clear acceptance criteria, dependencies, and a Definition of Done. Teams execute from a shared backlog, track progress and risks, and demonstrate work at sprint or milestone reviews.

The lifecycle connects initiation, planning, execution, release, and continuous improvement. The Project Manager coordinates delivery, timelines, risks, and communication; the Product Manager owns outcomes, prioritization, and success measures; developers build and test increments, QA validates acceptance, and stakeholders provide input and approvals. Daily standups and weekly delivery syncs surface progress and blockers, while regular stakeholder updates and a shared status source keep decisions visible.

Quality is part of the workflow: small pull requests receive review, automated tests and linting run in CI, and security scans, relevant integration and end-to-end smoke tests, and manual QA provide additional checks. Releases require acceptance criteria, CI and security checks, a rollback or mitigation plan, and post-deployment verification. Retrospectives after sprints, releases, milestones, or incidents convert lessons into a few owned, trackable improvement actions.
